# Global Development Rules

*Hinweis: Diese Regeln sind Teil der operativen Roo-SSOK. Die übergeordnete Governance-Definition befindet sich in `SSOK.md`.*

## General Behavior
- Work in small, focused changes.
- Do not refactor unrelated code.
- Prefer modifying existing files over creating new ones.
- Avoid unnecessary abstractions.

## Code Style
- Follow existing project structure and conventions.
- Keep functions small and readable.
- Do not introduce new dependencies unless necessary.

## Safety
- Never expose secrets or environment variables.
- Never modify `.env` files.
- Never change configuration without explanation.

## Editing Discipline
- Read relevant files before editing.
- Avoid speculative changes.
- Only change what is required to solve the task.

## Architecture Awareness
- Respect the existing architecture.
- Do not break module boundaries.
- Keep separation between domain, infrastructure and UI layers.

## Performance
- Avoid expensive operations unless required.
- Prefer simple deterministic solutions over complex ones.

## Communication
- Explain reasoning briefly before making changes.
- Keep responses concise.

## Windows PowerShell Command Compatibility

This project runs primarily on Windows PowerShell.

Agents must NOT generate commands using:

&&

Instead use PowerShell-compatible separators:

;

Examples:

Correct:
npm run lint; npm run typecheck; npm run test

Incorrect:
npm run lint && npm run typecheck && npm run test

Rationale:
PowerShell environments do not reliably support "&&" and this causes repeated execution failures and wasted agent iterations.

Scope:
All command suggestions generated by agents must follow PowerShell syntax.

## Windows Shell Assumption

This project runs primarily on Windows using PowerShell.

Agents must assume **Windows PowerShell** unless the user explicitly states that the shell is bash or zsh.

Do NOT generate commands that rely on bash or zsh syntax.

Examples of disallowed syntax:

export VAR=value
rm -rf folder
source .env
&& command chaining

Instead use PowerShell-compatible syntax.

Examples:

Correct PowerShell:

$env:VAR="value"
Remove-Item folder -Recurse -Force
npm run lint; npm run typecheck; npm run test

Incorrect Bash:

export VAR=value
rm -rf folder
npm run lint && npm run typecheck

Rationale:
Ensuring PowerShell-compatible commands avoids execution failures and reduces wasted agent iterations.

Scope:
All command suggestions generated by agents must follow Windows PowerShell compatibility unless another shell is explicitly requested.
