## Workflow Summary

Implemented `scripts/agent/run-review-gate-workflow.mjs`, a guarded review workflow that:

1. Reads a canonical handoff JSON from `--handoff <path>`.
2. Evaluates the handoff using review-gate-engine-compatible logic.
3. Writes a normalized review decision to `<output-dir>/review-decision.json`.
4. Creates `<output-dir>/prepared-review-evidence.json` only for `accepted` decisions.
5. Preserves the human approval gate by default and does not append review evidence unless explicitly authorized.

The workflow intentionally keeps review decision preparation separate from evidence append execution.

---

## CLI Interface

Supported flags:

- `--handoff <path>` — Required canonical handoff JSON input.
- `--output-dir <path>` — Adapter output directory; defaults to `.agent/out`.
- `--append` — Enables append mode; valid only with `--confirm-append`.
- `--confirm-append` — Confirms exactly one append to `review/review-results.jsonl`.
- `--dry-run` — Default-safe no-append mode; may still write adapter outputs under `.agent/out`.
- `--json` — Prints a machine-readable workflow summary.
- `--help` — Shows usage, default behavior, and safety constraints.

Example dry-run workflow:

```bash
node scripts/agent/run-review-gate-workflow.mjs --handoff .agent/out/handoff.json --output-dir .agent/out --dry-run --json
```

Human-approved append mode, for accepted decisions only:

```bash
node scripts/agent/run-review-gate-workflow.mjs --handoff .agent/out/handoff.json --output-dir .agent/out --append --confirm-append
```

## Safety Gates

The workflow enforces these gates:

- Rejects missing `--handoff`.
- Rejects malformed handoff input.
- Rejects unsupported decision values outside `accepted`, `needs_changes`, and `rejected`.
- Refuses `--confirm-append` without `--append`.
- Refuses `--append` without `--confirm-append`.
- Refuses `--dry-run` combined with `--append`.
- Never appends `needs_changes` or `rejected` decisions.
- Does not execute shell commands internally.
- Does not modify `ROADMAP.md`, `tasks/`, `runs/`, `validation/`, product code, Supabase files, or package files.

## Dry Run Behavior

Dry-run / no-append behavior is the default.

In this mode the workflow may write adapter outputs under `.agent/out` only:

- `.agent/out/review-decision.json`
- `.agent/out/prepared-review-evidence.json` only when the decision is `accepted`

When append flags are absent for an accepted decision, the CLI prints the required approval instruction:

```text
Review decision prepared.
Human approval required before append.
To append, rerun with --append --confirm-append.
```

For `needs_changes` or `rejected`, the workflow prints blockers and warnings and does not prepare append execution.

## Append Behavior

```bash
--append --confirm-append
```

Even with both flags, append is allowed only when the decision is `accepted`. The workflow appends exactly one normalized review event to `review/review-results.jsonl` using the existing Ralph state-transition append helper.
