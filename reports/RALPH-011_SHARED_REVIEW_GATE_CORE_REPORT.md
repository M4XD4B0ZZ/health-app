# Behavior Preservation

Decision behavior was intentionally preserved:

- Malformed handoff JSON still fails execution with a review-gate error.
- Unsupported or invalid handoff schema still produces critical findings and `rejected` decisions when parse succeeds.
- Critical findings still produce `rejected`.
- Warnings without critical findings still produce `needs_changes`.
- Missing optional metadata still produces warnings and therefore `needs_changes`.
- Passed validation with no warnings and done-equivalent task status still produces `accepted`.
- Workflow append remains blocked for `needs_changes` and `rejected` decisions.
- Workflow append still requires both `--append` and `--confirm-append`.
- Accepted decisions may still prepare review evidence input.

One implementation detail was parameterized for compatibility: `buildNormalizedReviewDecision` accepts a `workflowId` option so the workflow decision source continues to include `source.workflow`, while engine decisions do not.

# Known Limitations

- The shared core preserves the existing in-script structural validation approach; it does not introduce an external JSON Schema artifact.
- Review decisions include generated timestamps and random suffixes, so review IDs are intentionally non-deterministic while decision rules remain deterministic for the same handoff content.
- The required sample handoff for `RALPH-009` evaluates to `needs_changes` in the current repository state because runtime/evidence metadata is incomplete or unavailable for that generated handoff.
